** The Broken Code

Located in =~/.stumpwm.d/init.lisp= (lines 129-204, NOW REMOVED):

#+BEGIN_SRC lisp
(defparameter *eval-input-file* "/tmp/stumpwm-eval-input"
  "File where external scripts write code to evaluate.")

(defparameter *eval-output-file* "/tmp/stumpwm-eval-output"
  "File where evaluation results are written.")

(defparameter *eval-watcher-running* nil
  "Is the eval watcher running?")

(defparameter *eval-watcher-timer* nil
  "Timer for the eval watcher.")

(defun process-eval-request ()
  "Check for and process eval requests from file."
  (when (probe-file *eval-input-file*)
    (handler-case
        (let* ((code-str (with-open-file (stream *eval-input-file*
                                                 :direction :input)
                          (read-line stream nil nil)))
               (code (when code-str (read-from-string code-str)))
               (result (when code
                        (handler-case
                            (eval code)
                          (error (e)
                            (format nil "ERROR: ~A" e))))))

          ;; Write result to output file
          (with-open-file (stream *eval-output-file*
                                 :direction :output
                                 :if-exists :supersede
                                 :if-does-not-exist :create)
            (format stream "~A~%" result))

          ;; Delete input file to signal we're done
          (delete-file *eval-input-file*))

      (error (e)
        (with-open-file (stream *eval-output-file*
                               :direction :output
                               :if-exists :supersede
                               :if-does-not-exist :create)
          (format stream "ERROR: ~A~%" e))
        (when (probe-file *eval-input-file*)
          (delete-file *eval-input-file*))))))

(defun start-eval-watcher ()
  "Start watching for eval requests."
  (when *eval-watcher-running*
    (return-from start-eval-watcher))

  ;; Clean up any leftover files
  (when (probe-file *eval-input-file*)
    (delete-file *eval-input-file*))
  (when (probe-file *eval-output-file*)
    (delete-file *eval-output-file*))

  ;; Start timer that checks every 0.1 seconds
  (setf *eval-watcher-timer*
        (run-with-timer 0 0.1 #'process-eval-request))

  (setf *eval-watcher-running* t)
  (message "^2File-based eval watcher started^n"))

(defcommand eval-watcher-status () ()
  "Show eval watcher status."
  (message (format nil "File-based eval: ~A~%Input:  ~A~%Output: ~A"
                  (if *eval-watcher-running* "RUNNING" "STOPPED")
                  *eval-input-file*
                  *eval-output-file*)))

;; Auto-start file-based eval
(message "^3Starting file-based eval watcher...^n")
(start-eval-watcher)
#+END_SRC

* What Went Wrong

** Symptom

StumpWM entered a **crash loop** after adding this code:
- Window manager would start
- Immediately crash or freeze
- Session became unusable
- Had to revert from TTY to recover

** Root Cause (Hypothesis)

Multiple potential issues:

1. **High-frequency polling** - Timer running every 0.1 seconds (10 times per second)
   - Constant file system access (=probe-file= every 100ms)
   - CPU overhead in the window manager's main thread
   - Potential race conditions

2. **Unsafe eval** - Using =read-from-string= and =eval= on file contents
   - Could evaluate malformed Lisp code
   - No isolation from StumpWM's runtime
   - Errors in evaluated code could crash the WM

3. **File I/O in timer callback** - Synchronous file operations in event loop
   - Blocking I/O in the window manager's main thread
   - Could cause UI freezes or crashes
   - No timeout handling

4. **Race conditions** - File-based communication has inherent races
   - Input file could be read while being written
   - Delete operations could fail if file is locked
   - No proper synchronization mechanism

5. **Error handling issues** - Handler-case might not catch all crashes
   - Some Lisp errors might escape the handler
   - Could corrupt StumpWM's internal state
   - No recovery mechanism

** Why It Crashed (Best Guess)

Most likely causes in order of probability:

1. **Timer callback error** - =run-with-timer= callback threw uncaught exception
2. **File I/O blocking** - File operations blocked the main thread indefinitely
3. **Infinite error loop** - Error in =process-eval-request= triggered repeatedly by timer
4. **Resource exhaustion** - Too many file handles or memory from repeated operations

** Option 1: Use Existing Swank/Slynk REPL

**Pros:**
- Already implemented and working
- Battle-tested, won't crash
- Full REPL features
- Used by Emacs integration

**Cons:**
- Requires TCP client (not simple shell script)
- More complex protocol than file I/O
- Might need additional libraries

** Option 2: Unix Domain Socket

Create a socket at =/tmp/stumpwm.sock= that accepts commands.

**Pros:**
- More efficient than polling files
- Event-driven (no constant polling)
- Better for concurrent requests

**Cons:**
- More complex to implement
- Need socket handling in Common Lisp
- Still need to parse requests

** Option 3: Named Pipe (FIFO)

Use =mkfifo= to create =/tmp/stumpwm-pipe=

**Pros:**
- Blocking reads (no polling needed)
- Simple shell script interface
- Built-in synchronization

**Cons:**
- One request at a time (blocking)
- Pipe can break if process dies
- Need separate pipe for responses

** Option 4: Fix the File-Based Approach

Improve the original implementation:

**Changes needed:**
1. Longer poll interval (1 second instead of 0.1)
2. Better error handling
3. Timeout on file operations
4. Lock files for synchronization
5. Separate thread/process for I/O

** Option 5: HTTP Server in StumpWM

Embed a tiny HTTP server in StumpWM.

**Pros:**
- Can use =curl= from shell scripts
- Standard protocol
- Can handle concurrent requests
- Easy debugging

**Cons:**
- Need HTTP library (might be heavy)
- Port management
- Security concerns (localhost only)

** Option 6: Use stumpish

StumpWM has =stumpish= utility for sending commands.

**Pros:**
- Already exists
- Designed for this use case
- No additional code needed

**Cons:**
- Might not be installed
- Limited to StumpWM commands (not arbitrary Lisp eval)
- Need to check if it supports eval
